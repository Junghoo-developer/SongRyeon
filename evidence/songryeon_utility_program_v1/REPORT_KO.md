# RC6 제한적 감사 가능성 공개 증거 보고서

## 판정

이 공개 파생본이 지지하는 최대 주장은 **작성자가 함께 설계한 fixture 계약 안의 L1 제한적 감사 가능성**과 **결정론적 메커니즘 경계**다. AI 정확도 향상, 실제 사용자 효용, 현장 오류 차단, Node4의 추가 효용, 교차 도메인 일반화, 송련의 전반적 우월성은 입증하지 않는다.

## 독립 재계산 결과

- 작성 사례 24쌍에서 일반 로그의 감사 판정 재구성은 **17/24**, 연결 영수증은 **24/24**였다.
- 다섯 필드 평균 재구성 완전성은 **0.925 → 1.000**이었다.
- 작성 고정 입력 64개에서 일반 표시와 A/R 라벨만 붙인 표시의 출력 및 실제 출처 R 소비 결과는 **64/64 모두 동일**했다.
- clean-label 32개에서 A-only 필터는 실제 출처 R 소비를 **16/32 → 0/32**로 바꿨지만, 작성 정답 기준 정확도는 **16/32 → 16/32**로 같았다.

첫 결과는 모델 성능 비교가 아니라, 식별자·링크·인덱스·권한·digest가 추가된 기록 표현이 같은 작성 계약에서 경로를 더 완전하게 재구성하도록 돕는지 본 것이다. 두 표현의 전체 정보량은 같지 않다. 두 번째 결과는 라벨 장식 자체의 효과가 없고 필터의 소비 경로 변화가 정확도 향상으로 이어지지 않았다는 경계 자료다.

## 원 독립감사에서 유지한 결함

원 receipt 패킷은 외부 blind 검토용으로 안전하지 않았다. family를 드러내는 target 문자열 86건과 변경 표식 8건이 있었고 reveal 자료가 같은 패키지에 인접했다. 따라서 이 파생본은 원 패킷·reveal·family 식별자를 싣지 않으며 blind 결과라고 부르지 않는다.

원 manifest는 최상위 선언 파일만 확인했고 import cache 3개가 봉인되지 않았다. 이 파생본은 새 상대경로 manifest와 재귀적 exact-set 검증기로 그 배포 결함을 고쳤다. 그러나 서명이 없으므로 진본성·실행 증명·변조 불가능성을 뜻하지 않는다.

고정 입력 메커니즘 독립감사의 판정은 **REVISE**였다. 의미 정답이 공개 trace에 보였고, 현재 runtime에서는 `applied`라는 이름의 기록이 실제 상태 변경보다 먼저 남을 수 있는 반례가 재현됐다. 따라서 이 묶음은 실제 적용 완료, 사용자 수령, 성공 전달을 주장하지 않는다.

## 검증

`python -B verify_public.py`는 공개 행에서 수치를 다시 계산하고 선언 파일의 hash·크기·재귀적 파일 집합·주장 경계·개인정보 패턴을 함께 확인한다. `python -B -m unittest discover -s tests -v`는 정상 통과, 선언 데이터 변조 거부, 미선언 중첩 파일 거부를 검사한다. 둘 다 CPU만 사용하며 GPU·모델·네트워크 호출은 0이다.
