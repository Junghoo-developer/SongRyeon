# 송련 A/R 개입 지도와 현재 증거

작성일: 2026-08-07

## 한 문장 결론

송련에서 효과를 만드는 핵심은 로그에 `A`와 `R` 글자를 붙이는 행위 자체가
아니라, **모델의 해석 R이 코드 관측 A의 권한을 얻지 못하게 시야와 실행을
코드로 분리하고, 마지막에 A만 보는 감사 결과를 실제 라우팅에 적용하는 것**이다.

## A/R이 개입하는 여섯 층

| 층 | 실제 개입 | 코드 강제인가 | 기대 효과 |
|---|---|---|---|
| 기록 생성 | 출처·도구 결과·적용된 상태는 A, 발화·판단·답변은 R로 저장 | 예 | 나중에 누가 무엇을 관측/판단했는지 복원 |
| 에이전트 시야 | Node1·3은 A+R, Node2·4는 코드가 R을 제거한 A-only 시야 | 예 | 이전 모델 해석이 검증 근거로 세탁되는 경로 차단 |
| Node1 보존 | 모델은 보존 범위를 고르지만 코드는 숨김 원문에서 정확한 byte 범위만 A로 복사 | 예 | 모델 요약을 도구 원문처럼 위조하지 못하게 함 |
| Node2 | A-only로 증거 충분성 판정, reject 시 Node1 재수집 | 시야·라우팅은 코드, 충분성 판단은 모델 | 근거 없는 조기 답변 감소 |
| Node3 | A+R을 바탕으로 사용자 답변 R 작성 | 형식만 코드, 의미는 모델 | 사실과 해석을 함께 유용하게 서술 |
| Node4 | 최신 답변 R을 A-only 기록과 대조, reject 시 Node3 재작성 | 시야·횟수·라우팅은 코드, 판정은 모델 | 근거보다 강한 단정과 A/R 승격 교정 |

### 가장 강한 기계적 경계

1. `runtime/node_calls.py::NodeCaller._absolute_memory`
   - Node2와 Node4에 R을 전달하지 않는다.
   - `information_class`와 `code_verifiable`이 어긋나면 실행을 중단한다.
2. `nodes/retention.py::select_retained_content`
   - Node1의 review를 A로 바꾸지 않는다.
   - 실제 도구 원문의 `full`, `excerpt`, `chunk`만 코드가 복사한다.

이 두 지점은 모델이 지침을 어겨도 권한 경계를 코드가 유지한다. 반대로
Node2의 충분성, Node3의 서술, Node4의 의미 판정은 모델 체급과 프롬프트의
영향을 계속 받는다.

## 기존 탐색 실험이 보인 신호

2026-08-03 탐색 실험은 30개 합성 case를 seed 42·43·44로 반복하고,
`gemma4:26b`에 540회 모델 호출을 수행했다. 같은 증거 packet에서 prompt
조건과 reviewer 조건을 비교했다.

| 조건 | strict success | negative 근거 세탁 |
|---|---:|---:|
| 의미 없는 불투명 표지 | 65/90 (72.22%) | 15/45 (33.33%) |
| A/R 라벨만 설명 | 69/90 (76.67%) | 18/45 (40.00%) |
| A/R 소비 규칙 | 68/90 (75.56%) | 10/45 (22.22%) |
| 문체 placebo reviewer 적용 | 64/90 (71.11%) | 15/45 (33.33%) |
| 증거 reviewer 판정 적용 | 74/90 (82.22%) | 1/45 (2.22%) |

이 표에서 가장 큰 관측 신호는 증거 reviewer 적용이다.

- strict success: 문체 reviewer 대비 `+11.11%p`
- negative 근거 세탁: `-31.11%p`
- 같은 원 draft 대비 순교정: 7건 교정, 1건 회귀, 순 `+6`

반면 라벨만 붙인 조건은 근거 세탁이 불투명 표지보다 높았다. 따라서 현재
자료는 다음 우선순위를 지지한다.

1. A/R 라벨보다 실제 소비 권한을 분리한다.
2. 검증 노드에는 가능한 한 A-only 시야를 준다.
3. reviewer의 말만 기록하지 말고 permit/reject를 코드가 실제 결과에 적용한다.
4. 그 뒤 reviewer 모델 체급과 선택적 클라우드 라우팅을 최적화한다.

## 반드시 붙여야 하는 한계

위 수치는 이미 사용한 합성 case를 재사용한 탐색 결과다. 당시 사전
source-freeze와 사람 raw-packet 감사도 완전하지 않아 `publishable=false`로
판정됐다. 따라서 대회에서 다음처럼 말하면 안 된다.

- “A/R이 환각을 97.8% 제거했다.”
- “송련 전체가 일반 에이전트보다 통계적으로 우월하다.”
- “Node4의 단독 인과효과가 입증됐다.”

허용 가능한 표현은 다음 정도다.

> 재사용 합성 증거 replay에서 라벨만 제공한 조건보다, 증거를 대조하고 그
> 판정을 적용한 조건에서 근거 세탁이 더 적게 관측됐다. 이 신호를 독립된
> 후속 실험에서 다시 검증하고 있다.

## 로컬 노동 + 클라우드 감사 가설

구조적 가설은 다음과 같다.

- 로컬 모델: 도구 선택, 증거 수집, 초안 작성
- 추적 시스템: 모든 도구 결과·출처·상태 변화와 모델 판단을 A/R로 분리
- 클라우드 모델: 깨끗한 A-only packet과 최종 초안 R만 짧게 감사
- 코드: 감사 판정을 기록하고 차단·재작성 경로를 결정

이 구조가 유리할 수 있는 이유는 비싼 모델이 앞단 작업을 반복하지 않고,
가장 위험한 **사실 권한 승격** 구간에만 계산을 쓰기 때문이다. 그러나 다음은
실험 전에는 모른다.

- 클라우드 감사자가 로컬 감사자보다 실제로 오답을 더 잡는가
- 맞는 답을 과잉 차단하는 비용은 얼마인가
- 클라우드를 30개 전부가 아니라 위험 사례 8개 정도에만 써도 이득이 남는가
- 한 건의 순교정에 필요한 cloud call/token/latency가 얼마인가

이를 위해 `evals/hybrid_audit_v1/PROTOCOL.md`는 같은 frozen local draft를
`무감사 / 로컬 A-only 감사 / cloud A-only 감사 / 정적 8건 선택 감사`로
갈라 비교한다. 이 파일럿은 Node4 경계와 감사 모델 체급만 측정하며 Node1·2·3
전체 효과라고 확대 해석하지 않는다.
