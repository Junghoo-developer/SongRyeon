# ORDER 263: Competition Submission Readiness Checkpoint v0

## 1. 배경

SongRyeon Core는 2026년 오픈소스 개발자대회 참가 프로젝트로 접수됐다.
공식 운영규정은 전체 소스 공개, OSI 인증 라이선스, 제3자 구성요소와 모델 정보 공개,
심사 가능한 상태를 요구한다. 출품작 제출물에는 결과보고서, 3분 시연영상, 소스코드가 포함된다.

현재 로컬 구현은 ORDER 262와 475개 pytest 기준선까지 진행됐지만, 공개 `main`과 README는
이보다 뒤처져 있다. 또한 전체 `--pretty` 출력은 감사에는 유용하지만 첫 시연에는 너무 길다.

## 2. 목표

새 기능을 추가하지 않고, 심사자가 저장소를 이해하고 재현할 수 있는 최소 제출 기준선을 만든다.

## 3. 구현 범위

1. README 한글/영문 기준선을 2026-07-17 검증 결과로 갱신한다.
2. 제3자 구성요소 및 라이선스 고지 문서를 현재 작업 브랜치에 포함한다.
3. 모델 없이 실행되는 `fake-turn`에 `--compact` 표시 모드를 추가한다.
   - 기존 trace/data를 삭제하지 않는다.
   - 기존 절대정보 감사판과 최종 답변만 골라 표시한다.
   - code가 새로운 의미 답변을 생성하지 않는다.
4. DEMO 문서에 심사자용 3분 확인 순서를 추가한다.
5. ORDER 261/262를 포함한 현재 변경을 검증 가능한 체크포인트로 묶는다.

## 4. 금지

- L/R/0/1/2/3/4 실행 의미 변경
- 새 루프, 새 DB, 새 기억 정책 추가
- 모델 가중치 저장소 포함
- trace/data 원본 삭제 또는 compact 출력만 남기는 처리
- 테스트 수를 부풀리거나 GitHub Actions 미확인 상태를 통과로 표현

## 5. 완료 조건

1. `python main.py fake-turn "송련이 뭔지 짧게 설명해줘" --compact`가 짧은 감사판과 답변을 출력한다.
2. 같은 실행의 trace/data 원본은 기존 result에 보존된다.
3. README 한글/영문과 제3자 라이선스 문서가 서로 연결된다.
4. 비밀정보 탐색에서 추적 대상 파일의 실제 비밀값이 발견되지 않는다.
5. `python -m compileall songryeon_core main.py` 통과.
6. `python -m pytest` 통과.
7. `python main.py smoke-test` 통과.
8. 공개 원격 CI는 push 이후 별도로 확인하며, 확인 전에는 통과로 단정하지 않는다.
