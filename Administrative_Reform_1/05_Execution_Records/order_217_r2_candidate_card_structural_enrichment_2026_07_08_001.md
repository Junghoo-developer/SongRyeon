# ORDER 217 Execution Record: R2 Candidate Card Structural Enrichment

## Status

Implemented and partially live-tested on 2026-07-08.

## Goal

Improve Vessel R2 graph-node selection stability by adding code-copied
structural facts to each visible candidate card.

## Implemented Changes

- R2 candidate cards now include next-layer structure facts:
  - `child_candidate_visibility=structure_counts_only`
  - `child_candidate_count`
  - `child_candidate_kind_counts`
  - `child_branch_role_counts`
  - `child_data_kind_counts`
  - `child_summary_depths`
  - `has_child_candidates`
  - `has_summary_child_candidate`
  - `has_token_summary_child`
  - `has_leaf_summary_child`
  - `has_raw_original_child_candidate`
- R2 visible cards remove full `summary_text`.
- R2 prompt now explains that child structure fields are map signs, not selectable IDs.
- R2 prompt now discourages `none_selected` when structurally suitable candidate refs exist.
- R2 schema repair payload now marks valid failed selection refs so repair can preserve them while fixing enum fields.

## Meta-Information Boundary

- The added fields are generated by code from graph/read-packet structure.
- The added fields are absolute structural facts.
- Code does not choose which graph node is relevant.
- R2 remains responsible for semantic selection.
- R3 remains responsible for sufficiency/granularity/branch status.
