# ORDER 194 R Vessel Node0 Start Handoff Implementation 2026-07-03 001

## Summary

Implemented the first R/Vessel node_0 integration step.

Before this patch, `vessel-r-traverse` built an R Vessel read packet and passed it directly into the R traversal runtime.

After this patch, runtime records a separate node_0 memory packet before traversal:

```text
RLoopVesselReadPacketFrame
-> RLoopVesselStartHandoffPacketFrame generated by node_0
-> RLoopVesselTraverseResultFrame
```

## Code Changes

- Added `songryeon_core/core/r_loop_vessel_start_handoff.py`.
- Added `RLoopVesselStartHandoffPacketFrame`.
- Added `record_r_loop_vessel_start_handoff_packet(...)`.
- Connected `run_local_r_loop_vessel_traverse(...)` so it records the handoff after read packet creation.
- Added `start_handoff_packet_id` to `run_r_loop_vessel_traverse(...)`.
- Added handoff source IDs to traverse result source data IDs.
- Added terminal text line:

```text
node_0 Vessel R start handoff: status=... / packet=...
```

## Metainfo Boundary

The new handoff packet is absolute information.

It copies only code-known counts and IDs from the read packet:

- read packet ID
- optional graph guide packet ID
- optional graph snapshot ID
- entry/summary candidate counts
- available entry node IDs
- summary counts by data kind/depth
- recent memory counts when supplied

It does not choose relevant nodes, summarize graph memory, claim R success, or convert Vessel material into L document evidence.
