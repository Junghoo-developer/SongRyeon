# SongRyeon Core v1 3분 시연 대본 초안

> 목표 길이: **2분 50초 내외**, 최종 영상은 3분 이하
>
> 실제 실행 결과가 이 대본과 다르면 영상을 편집해 숨기지 말고 원인을
> 수정한 뒤 새로 촬영한다. 화면에는 격리된 데모 로그만 사용하며 개인정보,
> API 키와 실제 `memory/memory.jsonl`을 노출하지 않는다.

## 촬영 전 준비

```powershell
ollama serve
ollama pull gemma4:26b
python -m pip install -e ".[test]"
python -m pytest -q
```

- [ ] 제출 커밋과 `git status --short`를 확인
- [ ] 깨끗한 clone에서 전체 테스트가 통과한 최종 수치를 자막에 반영
- [ ] `.tmp/demo-video-memory.jsonl`이 새 파일인지 확인
- [ ] 제출 모델 태그와 digest가 화면에 표시되는지 확인
- [ ] 터미널 글자 크기와 한국어 음성이 읽히는지 확인
- [ ] 최종 영상 길이 3분 이하 확인
- [ ] 화면에 표시할 Git SHA·테스트 수치는 `TODO`가 아니라 최종 값인지 확인

## 타임라인과 내레이션

### 0:00–0:20 — 문제와 한 문장 소개

화면: 저장소 README 제목과 구조 요약

내레이션:

> “LLM 에이전트가 실제로 읽은 코드와 스스로 만든 판단을 섞으면 실행 동선을
> 추적하기 어렵습니다. 송련 코어는 코드가 확인한 A와 모델이 만든 R을
> 원자 기록으로 분리하고, 네 노드가 증거 수집부터 최종 검열까지 나누어
> 처리하는 로컬 오픈웨이트 에이전트 런타임입니다.”

### 0:20–0:40 — 실행 경계 확인

화면:

```powershell
python -m demo --help
```

내레이션:

> “공식 시연은 외부 상용 API fallback 없이 로컬 Ollama의
> `gemma4:26b`를 사용합니다. 실제 기억 대신 이번 영상 전용 JSONL 경로를
> 지정하겠습니다.”

### 0:40–1:35 — 한 턴 실제 실행

화면:

```powershell
python -m demo --memory .\.tmp\demo-video-memory.jsonl `
  "memory/record.py를 실제 도구로 읽고 기록의 일곱 필드와 A/R 분류 방식을 설명해 줘."
```

내레이션:

> “사용자는 특정 파일을 실제로 읽고 설명하라고 요청했습니다. Node1만
> 읽기 전용 도구를 쓸 수 있고, 도구 결과에서 다음 노드가 볼 원문을
> 선택합니다. Node2는 그 원문이 요청에 충분한지 검사합니다. Node3가
> 답변을 만들면 Node4가 답변의 구체적인 코드 주장을 선택된 A 원문과
> 대조합니다.”

화면에서 짚을 것:

- Ollama 버전, 모델 이름과 digest 표시
- Node1의 `read_python_file` 실행
- 원문 보존 결과
- Node2와 Node4의 permit/reject
- 최종 답변과 도구·반려 횟수

주의:

- Node2 또는 Node4 한도 초과 경고가 나오면 정상 성공처럼 설명하지 않는다.
- 모델이 파일을 제대로 읽지 못했다면 해당 실행은 보존하고 원인을 수정한
  뒤 다시 촬영한다.

### 1:35–2:10 — 원본 로그와 에이전트 시야

화면: `memory/record.py`, `memory/agent_view.py`의 핵심 부분과 격리 로그

내레이션:

> “원본 JSONL의 각 원자는 본문, A/R 분류, 코드 확인 가능 여부, 정보 종류,
> 턴 ID, 정보 ID, UTC 시각의 일곱 필드를 가집니다. 에이전트에게는 모든
> 원본을 그대로 쏟지 않고 숨김 종류를 제외한 파생 시야를 제공합니다.
> 최초 약 8천 자에서 잡은 가장 오래된 원자를 턴이 끝날 때까지 기준점으로
> 고정해, 뒤 노드가 앞 노드의 증거를 잃지 않게 했습니다.”

개인정보 없는 격리 로그만 잠깐 보여준다. 모델 prompt 전체를 길게 스크롤하지
말고 A/R 필드와 서로 다른 `information_type`이 보이는 구간에 집중한다.

### 2:10–2:35 — 안전 경계와 재현성

화면: `agent_tools/files.py`, 테스트 결과, `evals/README.md`

내레이션:

> “파일 도구는 프로젝트 안의 UTF-8 Python 파일 목록과 읽기만 허용하고,
> 절대경로와 루트 이탈을 코드가 막습니다. 테스트는 임시 경로를 사용해 실제
> 기억을 바꾸지 않습니다. 비교평가 골격은 고정 case와 원문 hash를
> 검사하며, 현재 합성 fixture 결과를 실제 모델 성능으로 주장하지 않습니다.”

화면 자막:

```text
시연 Git SHA: TODO — 최종 커밋 동결 후 입력
깨끗한 clone 전체 테스트: TODO — 촬영 직전 실제 출력 입력
비교평가: 사람 검수 전 탐색 결과는 공식 성능 수치로 사용하지 않음
```

### 2:35–2:50 — 한계와 마무리

화면: 아키텍처 그림 또는 README의 “아직 없는 것”

내레이션:

> “현재 데모는 Python 읽기 전용 조사에 집중하며 기억 검색과 압축은 다음
> 단계입니다. 송련은 모델이 항상 옳다고 주장하지 않습니다. 모델의 판단과
> 코드가 확인한 실행 사실을 분리해, 사람이 다시 추적할 수 있게 만드는
> 것이 이번 버전의 핵심입니다.”
