# SongRyeon Core v1 — 2분 50초 시연 패키지

> 목표 재생 시간: **2분 50초**, 대회 제한: **3분 이하**
>
> 이 대본은 현재 동결 실험과 사람 감사 결과에 맞춘 촬영본이다. 영상에는
> 실제 `memory/memory.jsonl`, `.tmp` 원시 로그, 모델 thinking, blind key,
> API 키, 계정 정보, 사용자 이름이 포함된 절대경로를 노출하지 않는다.

## 1. 촬영 직전 준비

아래 검증은 녹화 전에 실행한다. 전체 테스트와 현재 Git SHA를 확인하지만,
원시 평가 로그나 blind ID는 출력하지 않는다.

```powershell
powershell -ExecutionPolicy Bypass -File .\submission\video_capture.ps1 -Mode verify
```

검증이 끝난 뒤 실제 시연은 아래 한 줄로 시작한다. 스크립트는 화면을 지우고
매번 새로운 `.tmp/video-capture/.../memory.jsonl`을 만든다. 기존 기억 파일은
읽거나 덮어쓰지 않는다.

```powershell
powershell -ExecutionPolicy Bypass -File .\submission\video_capture.ps1 -Mode demo
```

촬영 전 체크:

- [ ] Git 작업 트리가 clean이며 영상에 나온 SHA가 제출 SHA와 같다.
- [ ] 검증 스크립트가 출력한 최신 테스트 결과를 아래 자막에 그대로 쓴다.
- [ ] `gemma4:26b`, Ollama 버전, 모델 digest가 터미널에서 식별된다.
- [ ] 터미널 글자는 모바일 화면에서도 읽히는 크기다.
- [ ] 바탕화면 알림, 계정 이름, 이메일, 전화번호를 모두 가렸다.
- [ ] 격리 JSONL의 **경로와 내용은 영상에서 열지 않는다.**
- [ ] 결과가 대본과 다르면 성공처럼 편집하지 않고 원인을 확인한 뒤 새로 찍는다.

## 3. 자막 파일에 그대로 옮길 짧은 문장

1. 송련은 코드가 확인한 A와 모델이 만든 R의 권한을 분리한다.
2. Node1만 도구를 쓰고 Node2가 증거 충분성을 판단한다.
3. Node3가 답변하고 Node4가 공개 보존 A와 다시 대조한다.
4. 시연은 매번 새 `.tmp` JSONL을 사용하며 실제 기억을 건드리지 않는다.
5. 같은 상수의 선언과 실제 검증 로직의 집행은 서로 다른 주장이다.
6. 동결 실험은 24 case × 3 구조 × 3 seed, 총 216회다.
7. 첫 verdict는 71/72, 72/72, 72/72였으며 성능 우월성은 입증되지 않았다.
8. 사람 감사 19개에서 parse 19/19, 근거와 A/R 출처는 각각 18/19였다.
9. publication integrity 통과는 성능 우월성 통과가 아니다.
10. 송련은 환각 완전 제거가 아니라 실패의 추적과 수정을 목표로 한다.

## 4. 촬영·업로드 최종 체크

- [ ] 실제 재생 시간이 2분 50초 전후이며 반드시 3분 이하이다.
- [ ] 녹화 당일 `video_capture.ps1 -Mode verify`의 테스트 결과를 자막에 사용했다.
- [ ] 영상의 Git SHA가 공개 저장소의 제출 SHA와 정확히 같다.
- [ ] `publishable: true`를 “성능 우월”이 아닌 “publication integrity 통과”로 설명했다.
- [ ] Node4의 추가 성능 효과를 주장하지 않았다.
- [ ] 사람 감사가 19개 표본이며 감사자가 프로젝트 소유자임을 밝혔다.
- [ ] 216개 전체 설명, 실제 업무 일반화, 환각 제거를 주장하지 않았다.
- [ ] 원시 JSONL, thinking, blind key, 절대경로, API 키, 개인정보가 한 프레임도 나오지 않는다.
- [ ] 음성과 자막을 모바일에서 읽을 수 있다.
- [ ] YouTube 링크를 로그아웃·시크릿 창에서도 열 수 있다.
- [ ] 최종 영상 URL을 결과보고서와 참가자 페이지에 같은 값으로 입력했다.

## 5. 문제가 생겼을 때

- 모델이 두 파일을 모두 읽지 않았다면 그 실행을 보존하되 성공 사례로 쓰지 않는다.
- 답변이 중간에 끊겼다면 검증 미완료로 표시하고 모델 출력을 편집해 완성하지 않는다.
- Node4가 잘못 permit했다면 숨기지 말고 실패 사례로 분리한다.
- 촬영 직전 테스트 수가 문서와 다르면 최신 clean SHA에서 다시 실행한 수치만 쓴다.
- 영상 시간이 넘으면 결과나 한계를 삭제하지 말고, 코드 화면 전환 시간을 줄인다.
