# SongRyeon Core v1 AI 모델 활용·라이선스 기술명세 초안

> 상태: **공식 결과보고서에 옮기기 전 내부 초안**
>
> 현재 저장소의 실행 정책과 구현을 기준으로 작성했다. 모델 digest와 라이선스는
> 확인했으며, 제출 시 최종 시연 환경·Git SHA와 AI 코딩 보조 사용 기간을 보완한다.

| 구분 | 사용 여부 | 설명 |

## 3. 비교 구조와 과거 탐색 기준선

공식 v2 holdout은 모델 체급 차이를 섞지 않는다. 같은 `gemma4:26b`,
temperature 0, context 16,384, 최대 도구 호출 3회 조건에서 Node2·Node4가
없는 단일 에이전트, Node4 제외 송련, 전체 송련을 비교한다. seed는 1709, 2647,
3911이며 실행 순서를 block마다 바꿨다.

`qwen3:14b`는 더 작은 로컬 **과거 탐색 기준선**이다. 현재 재현 문서에는
Ollama model ID `bdbd181c33f2`, `Q4_K_M`, 약 9.3 GB로 기록되어 있다. 이
모델은 v2 공식 비교군, 대회용 기본값 또는 오류 시 대체 모델이 아니며,
`gemma4:26b`의 v2 결과와 섞어 집계하지 않는다.

## 4. 모델이 담당하는 부분과 코드가 담당하는 부분

하나의 설정된 model client를 네 논리 역할에서 호출한다.

| 노드 | 모델의 역할(R) | 코드의 통제(A) |
|---|---|---|
| Node1 | 사용할 도구, 보존 방식과 다음 행동 제안 | 허용 도구, 프로젝트 경계, 실행 횟수, 실제 원문 복사와 라우팅 |
| Node2 | 증거 충분성 `permit`/`reject` 판단 | 반려 횟수와 실제 다음 노드 적용 |
| Node3 | 사용자에게 줄 자연어 답변 작성 | 답변 원문과 출처·턴 기록 |
| Node4 | 답변의 A 왜곡 여부 `permit`/`reject` 판단 | 반려 횟수, 최종 선택과 검증 미완료 상태 기록 |

모델 응답은 JSON Schema 형식으로 요청하고 파서가 필드, 값, 길이를 검사한다.
계약에 맞지 않으면 제한된 횟수만 다시 요청한다. 모델은 A 원문을 직접
작성하지 않는다. 도구 결과의 공개 구간은 코드가 숨김 원문에서 `full`,
문자 위치 `excerpt` 또는 결정론적 `chunk`로 그대로 복사한다.

## 5. A/R 정보 경계

- A: 코드가 확인한 노드, 도구, 경로, 성공 여부, 카운터, 실제 선택 원문,
  UUID와 UTC 생성 시각
- R: 사용자 발화의 내용, 모델의 이유·검토·답변·제안
- 모델 입출력 원문과 도구 원문은 감사용 원본 JSONL에 남지만 일반 에이전트
  시야에서는 숨김
- 에이전트 시야는 턴 시작 시 최신 약 8,000자에서 원자 단위로 선택하고
  그 턴 동안 기준점을 고정

이 경계는 모델이 만든 모든 내용의 진실을 보장하지 않는다. 코드로 확인할
수 있는 실행 사실을 모델의 서술과 분리하고 추적하는 것이 현재 범위다.

## 6. 입력 데이터와 보안 경계

- 기본 대회 실행은 로컬·자체 호스팅 Ollama만 사용한다.
- 실제 `memory/memory.jsonl`은 개인정보가 포함될 수 있어 Git과 배포에서
  제외한다.
- 파일 도구는 프로젝트 루트 안의 허용된 UTF-8 `.py`만 읽는다.
- 절대경로, 루트 이탈, 제외 폴더, 크기 상한 초과를 코드가 거부한다.
- 모델 API 키는 기본 실행에 필요하지 않다.

외부 API 통합시험은 `--external-api-integration`을 사용자가 명시해야 한다.
실제 기본 기억 경로 사용을 코드가 거부하며, 경로를 지정하지 않으면 삭제되는
임시 JSONL을 사용한다. 환경 변수에서만 API 키를 읽고, 자격증명을 명령행,
설정 파일, 기억 로그나 평가 산출물에 저장하지 않는다. 이 시험의 결과는
대회용 성능 집계에서 제외한다.

`--codex-account-integration` 경로도 대회용 로컬 런타임이 아니다. 이는
저장된 Codex 계정을 이용한 선택적 모델 체급·통합시험이며, 공개 또는 합성
입력과 폐기 가능한 격리 로그로만 수행한다. 이 결과는 `gemma4:26b`의 공식
시연 결과나 동일 조건 성능 비교로 합산하지 않는다.

## 7. 알려진 한계

- 모델 판단과 답변 자체는 R이며 오류가 남을 수 있다.
- temperature와 seed를 고정해도 실행 환경과 모델 런타임에 따라 완전한
  결정성을 보장하지 않는다.
- Node2·Node4 반려 한도를 넘으면 유한 종료를 위해 결과를 반환할 수 있으나,
  CLI와 결과 객체가 검증 미완료 상태를 표시한다.
- 현재 Node1의 도구는 Python 파일 목록과 읽기에 한정된다.
- v2 합성 holdout의 기계 verdict에서 `songryeon-full`과
  `songryeon-no-node4`는 모두 72/72로 동률이었다. 이 집합은 Node4의 추가
  효과를 입증하지 않으며, full은 평균 모델 호출 6.833회·평균 지연 20.035초로
  no-Node4의 5.083회·15.656초보다 비쌌다.
- Node2·Node4가 없는 단일 에이전트 기준선은 71/72였다. 한 건은 private
  raw에 `ModelResponseError`인 유효 JSON 응답 실패로 기록된 미완료이며,
  의미 판정 오답은 아니지만 사전 등록 규칙에 따라 분모에 포함해 오답 처리했다.
  이 한 점 차이를 시스템 우월성으로 확대 해석하지 않는다.
- 기계 채점은 첫 verdict만 측정한다. 참가자가 필수 blind 19개를 감사한 결과
  parser와 실제 답변·미완료 상태는 19/19가 일치했고, fixture 근거성과 A/R
  권한·출처 표기는 각각 18/19였다. 나머지 1건은 모델 응답이 `null`인 미완료
  사례로 평가할 설명이 없었다. publication integrity gate의 `publishable: true`는
  공개 증거 사슬의 무결성 상태이며 성능 우월성이나 설명 전체 검증이 아니다.
- 모델 호출·지연 수치는 격리 원시 capture에서 사후 계산한 운영 지표로,
  사전 등록 metric이나 공개 proof 체인의 검증 대상이 아니다. seed 반복은
  독립 case가 아니며 full/no-Node4는 독립 end-to-end 실행이므로 Node4의
  순수 인과효과나 통계적 유의성을 뜻하지 않는다.
