# SongRyeon Core v1 AI 모델 활용·라이선스 기술명세 초안

> 상태: **공식 결과보고서에 옮기기 전 내부 초안**
>
> 현재 저장소의 실행 정책과 구현을 기준으로 작성했다. 제출 시 실제 모델
> 전체 digest, 라이선스 원문, 시연 환경과 AI 코딩 보조 이력을 보완한다.

## 1. AI 사용 유형

| 구분 | 사용 여부 | 설명 |
|---|---|---|
| 출품작 내 생성형 AI 추론 | 사용 | 네 논리 노드가 설정된 로컬·자체 호스팅 모델을 호출 |
| 오픈웨이트 모델 | 사용 | 대회용 기본 프로필은 `gemma4:26b` |
| 외부 상용 API 자동 fallback | 사용하지 않음 | 로컬 모델 오류는 명시적 실패로 끝남 |
| 외부 API 통합시험 | 선택적 | 명시적 플래그와 격리 로그로만 실행, 공식 집계에서 제외 |
| 개발 중 AI 코딩 보조 | 사용 | OpenAI Codex로 설계 토론, 코드·테스트·문서 작업을 보조하고 참가자가 방향과 채택 여부를 결정 |

## 2. 제출·시연 모델

| 항목 | 값 |
|---|---|
| 실행 프로필 | `contest_local_or_self_hosted` |
| 런타임 | Ollama |
| 모델 태그 | `gemma4:26b` |
| 현재 기록된 모델 ID | `5571076f3d70` |
| 파라미터·양자화 | 25.8B, `Q4_K_M` |
| 현재 저장소의 라이선스 기록 | Apache License 2.0 |
| 기본 요청 컨텍스트 | 16,384 |
| temperature / seed | 0 / 42 |
| 모델 전체 digest | `5571076f3d70050487b26b341705799e0ab29b808164f90d20d4cf84f699d251` |
| 공식 모델 출처·라이선스 원문 재확인 | 2026-07-30, Ollama 모델 페이지와 로컬 `ollama show --license`에서 Apache-2.0 확인 |

모델은 참가자 PC 또는 참가자가 통제하는 자체 호스팅 Ollama 서버에서
직접 실행한다. 소스 저장소는 모델 가중치와 Ollama 실행 파일을 포함하거나
재배포하지 않는다.

## 3. 비교 기준선

`qwen3:14b`는 더 작은 로컬 비교 기준선이다. 현재 재현 문서에는 Ollama
model ID `bdbd181c33f2`, `Q4_K_M`, 약 9.3 GB로 기록되어 있다. 이 모델은
대회용 기본값이나 오류 시 대체 모델이 아니며, `gemma4:26b` 결과와 섞어
집계하지 않는다. 제출 시 정확한 전체 digest와 라이선스를 다시 기록한다.

## 4. 모델이 담당하는 부분과 코드가 담당하는 부분

하나의 설정된 model client를 네 논리 역할에서 호출한다.

| 노드 | 모델의 역할(R) | 코드의 통제(A) |
|---|---|---|
| Node1 | 사용할 도구, 보존 방식과 다음 행동 제안 | 허용 도구, 프로젝트 경계, 실행 횟수, 실제 원문 복사와 라우팅 |
| Node2 | 증거 충분성 `permit`/`reject` 판단 | 반려 횟수와 실제 다음 노드 적용 |
| Node3 | 사용자에게 줄 자연어 답변 작성 | 답변 원문과 출처·턴 기록 |
| Node4 | 답변의 A 왜곡 여부 `permit`/`reject` 판단 | 반려 횟수, 최종 선택과 검증 미완료 상태 기록 |

모델 응답은 JSON Schema 형식으로 요청하고 파서가 필드, 값, 길이를 검사한다.
계약에 맞지 않으면 제한된 횟수만 다시 요청한다. 모델은 A 원문을 직접
작성하지 않는다. 도구 결과의 공개 구간은 코드가 숨김 원문에서 `full`,
문자 위치 `excerpt` 또는 결정론적 `chunk`로 그대로 복사한다.

## 5. A/R 정보 경계

- A: 코드가 확인한 노드, 도구, 경로, 성공 여부, 카운터, 실제 선택 원문,
  UUID와 UTC 생성 시각
- R: 사용자 발화의 내용, 모델의 이유·검토·답변·제안
- 모델 입출력 원문과 도구 원문은 감사용 원본 JSONL에 남지만 일반 에이전트
  시야에서는 숨김
- 에이전트 시야는 턴 시작 시 최신 약 8,000자에서 원자 단위로 선택하고
  그 턴 동안 기준점을 고정

이 경계는 모델이 만든 모든 내용의 진실을 보장하지 않는다. 코드로 확인할
수 있는 실행 사실을 모델의 서술과 분리하고 추적하는 것이 현재 범위다.

## 6. 입력 데이터와 보안 경계

- 기본 대회 실행은 로컬·자체 호스팅 Ollama만 사용한다.
- 실제 `memory/memory.jsonl`은 개인정보가 포함될 수 있어 Git과 배포에서
  제외한다.
- 파일 도구는 프로젝트 루트 안의 허용된 UTF-8 `.py`만 읽는다.
- 절대경로, 루트 이탈, 제외 폴더, 크기 상한 초과를 코드가 거부한다.
- 모델 API 키는 기본 실행에 필요하지 않다.

외부 API 통합시험은 `--external-api-integration`을 사용자가 명시해야 한다.
실제 기본 기억 경로 사용을 코드가 거부하며, 경로를 지정하지 않으면 삭제되는
임시 JSONL을 사용한다. 환경 변수에서만 API 키를 읽고, 자격증명을 명령행,
설정 파일, 기억 로그나 평가 산출물에 저장하지 않는다. 이 시험의 결과는
대회용 성능 집계에서 제외한다.

## 7. 알려진 한계

- 모델 판단과 답변 자체는 R이며 오류가 남을 수 있다.
- temperature와 seed를 고정해도 실행 환경과 모델 런타임에 따라 완전한
  결정성을 보장하지 않는다.
- Node2·Node4 반려 한도를 넘으면 유한 종료를 위해 결과를 반환할 수 있으나,
  CLI와 결과 객체가 검증 미완료 상태를 표시한다.
- 현재 Node1의 도구는 Python 파일 목록과 읽기에 한정된다.
- 실제 모델 간 성능 차이는 아직 검토 완료된 라이브 평가 수치로 확정되지
  않았다.

서비스 사용 시작일과 제공 모델 표시는 계정·도구 기록을 보고 제출 직전에
보완한다.

| 사용 모델 또는 확인 가능한 제품 버전 | `TODO: 계정·도구 기록에서 최종 확인` |

| 사람이 직접 수행한 검토 | 참가자가 목표·철학·노드 역할을 결정하고 실제 데모 출력과 프롬프트를 검토해 수정을 요청; 채택 변경은 회귀 테스트로 확인 |

권장 공개 문장:

> OpenAI Codex를 설계 토론, 코드·테스트 작성과 문서 검토 보조에
> 활용했다. 참가자가 목표와 구조를 결정하고 실제 데모 출력과 프롬프트를
> 반복 검토했으며, 채택한 변경은 회귀 테스트로 확인했다. 실행 모델과
> 코딩 보조 서비스는 서로 구분해 기록했다.

제공 모델명은 추측하지 않고 계정 또는 도구 기록에서 확인되는 값만 최종
기재한다.
